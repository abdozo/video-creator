# Rigby2D integration research

Reviewed on 2026-11-09. The latest tagged release checked was v0.5.0 at `d3cc401`. The hosted editor follows `develop`, so use a pinned checkout for repeatable experiments and verify its advertised tools with `tools/list`. [Release](https://github.com/jaisurya-dev-art/rigby2d/releases/tag/v0.5.0) · [Installation guide](https://rigby2d.com/docs/installation.html)

## What Rigby2D provides

Rigby2D animates layered artwork with reusable rigs, weighted meshes, IK, constraints and keyframes. AutoRig builds a rig from separate body-part layers. The editor takes PSD, SVG or correctly aligned PNG layers. The MCP AutoRig tools accept PSD or an unrigged `.rigby` work file. A character made from a flat illustration needs a separate art preparation step. Keep alternate hands and mouth shapes on their own layers and review the joints and weights after AutoRig. [AutoRig guide](https://rigby2d.com/docs/autorig.html) · [MCP tool reference](https://rigby2d.com/docs/mcp-tools.html#autorig)

Film scenes can stage multiple characters with clips, crossfades, camera moves, foreground and background parallax, and audio. Actors' character files are embedded by value, so a revised character must be inserted into the scene again. MCP can add actors, place clips, set transforms and set layer depth in an existing stage file. The editor can export a shot with its audio or export a scene manifest with the stage and actor skeletons and texture atlases. [Scenes guide](https://rigby2d.com/docs/scenes.html)

## Where automation stops

| Route | Output | Integration |
| --- | --- | --- |
| MCP scene and rig tools | Editable `.rigby` projects with keys, actors, clips and lip-sync. | Codex can inspect rigs, batch edits and sample poses. Keep a canonical rig and edit shot copies. [MCP guide](https://rigby2d.com/docs/mcp.html) |
| MCP `export_sprite_sheet` with `format: "frames"` | A selected skeletal animation as standalone PNG frames using the CPU renderer. FPS, scale, skin and looping are configurable. | Feed a transparent character sequence to Remotion. Verify registration, frame count, padding and render time at the target resolution. Use `loop: false` for a dialogue shot and validate the end frame. [MCP export tool](https://rigby2d.com/docs/mcp-tools.html#export_sprite_sheet) · [Export guide](https://rigby2d.com/docs/export.html) |
| Editor Film render | Camera-framed PNGs, VP9 WebM with alpha, or MP4 with mixed audio. | Open and render the shot in the editor. Let Remotion own the final mix and mute audio carried by the shot clip to avoid doubling dialogue. [Film rendering guide](https://rigby2d.com/docs/film.html#rendering) |
| Custom render with the JavaScript runtime | Pixels from skeleton JSON and texture atlases, or a scene manifest and its exported assets. | Build a headless browser capture step if automated shots need full scene framing. Evaluate at a fixed step from shot start for physics and render to cached frames or clips. Verify against the editor before relying on it. [Runtime guide](https://rigby2d.com/docs/runtimes.html#javascript) · [Scene export guide](https://rigby2d.com/docs/scenes.html#in-games-and-apps) |

The MCP guide's limitation on PNG sequences refers to **Film rendering**. The sprite-sheet tool can produce per-animation PNG frames, and its tool contract exposes no stage camera, multi-actor scene or audio mix controls. Film output settings can be written via MCP, while the documented Film render command lives in the editor. A production pipeline can render actor passes in MCP and stage them in Remotion, or use a custom renderer for full Rigby2D scenes. Treat parity for clipping, physics, blend modes and parallax as a test result. [MCP guide](https://rigby2d.com/docs/mcp.html) · [MCP tool reference](https://rigby2d.com/docs/mcp-tools.html)

## Audio and timing

Use the same line audio for lip-sync and the final mix. In Rigby2D, attach the WAV to a named animation, set the track offset if the line begins after the shot starts, and call `lip_sync` with an explicit mouth slot and mapping. The timing file accepts `[{ "word": "...", "start": 0, "end": 0.2 }]` in seconds relative to the start of that audio file. The tool uses the track offset when writing keys and clips the generated region to the animation duration. Start from the already aligned words and convert their clock to track-relative time once. Mouth changes become attachment keys and can play in the exported skeleton. [MCP lip-sync implementation](https://github.com/jaisurya-dev-art/rigby2d/blob/develop/src/mcp/film.js) · [Lip-sync guide](https://rigby2d.com/docs/lip-sync.html)

The editor lists Arabic for Whisper transcription. In v0.5.0 the word-to-viseme function strips letters outside the Latin alphabet. A local call with `بص` returned no mouth shapes. For Egyptian Arabic, supply reviewed mouth cues through the supported Rhubarb-style timing format or key the mouth attachments directly. A volume-driven mouth control can give a first preview while explicit mouth cues are prepared. [Lip-sync guide](https://rigby2d.com/docs/lip-sync.html) · [Pinned word-to-viseme implementation](https://github.com/jaisurya-dev-art/rigby2d/blob/v0.5.0/src/core/lipsync.js#L160)

## Local setup and rights

The MCP server uses Node.js 20+ and stdio. Run `node /path/to/rigby2d/src/mcp/server.js --root /path/to/shot-workspace` from a pinned checkout. The server checks paths against its roots and resolves symlinks before checking. Install the checkout dependencies if using PSD import or the Python tool. Browser and local development editors are available. Release v0.5.0 lists a universal macOS DMG for Apple silicon and Intel on macOS 10.15+, and its release notes mark it as unsigned. [MCP setup](https://rigby2d.com/docs/mcp.html#setup) · [Installation](https://rigby2d.com/docs/installation.html) · [Release downloads](https://github.com/jaisurya-dev-art/rigby2d/releases/tag/v0.5.0)

The project offers MIT or Apache-2.0 for its code. Rigby2D branding and the NILA, Rigbytron and scene-demo assets have separate terms. Use original art, rigs and dialogue for a public pilot, and retain the required notices for the selected code license if shipping the runtime. [Upstream trademarks and demo rights](https://github.com/jaisurya-dev-art/rigby2d/blob/develop/TRADEMARKS.md)

## Local verification

A temporary checkout at v0.5.0 commit `d3cc4010f41da43ff970154756b4c000110bdcc7` ran under Node 22.13 on this Mac. The stdio server listed 41 tools. A one-second animation on a copy of the NILA demo rig took two supplied English word timings and a silent WAV fixture, produced seven mouth keys, and exported 25 PNGs at 24 fps with `loop: false`. At scale 0.35, the frames were 465 × 890, contained transparent and opaque pixels, and had seven distinct image hashes. The CPU export took about 2.6 seconds for this fixture. The same export call rejected the upstream multi-actor scene file. The sprite-sheet suite passed all nine tests. The broader MCP run passed 15 checks and hit two dependency errors for Python scripting and PSD support in the bare checkout. The fixture checks file exchange and image output. A voiced Remotion render and performance at production resolution still need measurement. ## Integration with Video Factory

Start with a character-rendering step beside Remotion. Use a canonical layered rig with named actions, supported head angles, mouth attachments and an origin. Each shot works on a copy. Codex can use MCP to audition poses and write a take. A repeatable batch command can then take a saved shot specification, apply its edits and export numbered transparent PNGs. Scope the server to the shot workspace and pin the Rigby2D version. Save the frame list, FPS, placement anchor and source hashes with the take. Confirm registration across different actions, since sprite bounds depend on the requested animations.

Keep `tools/prepare_narration.py` as the single AI voice path. After it generates and fits the continuous performance, cut each dialogue WAV from the fitted audio, then convert `vo[].words` to Rigby2D's `word` field and subtract the cut's project start from each word time. Place the WAV at its shot-local offset in Rigby2D. Remotion uses the project clock and master mix. Match FPS across the two steps and use the shot's explicit frame count in Remotion. The one-second export included both endpoints, so a 24-frame shot consumes frames 0 through 23. Remotion places the actor, moves the camera, cuts between shots, adds captions and SFX, and writes the MP4 using the existing pipeline. [Narration timing and mix](../tools/prepare_narration.py#L392) · [Remotion render entry point](../remotion/scripts/render-all.mjs#L24)

Prove the workflow with 12–20 seconds of the railway scene. Use the same original character in a wide shot where he walks and stops, followed by a close-up where he looks up at the moth, reacts and says one line. Author the upward head view or face deformation in the rig. Review foot contact, eyeline, mouth closure, continuity across the cut and transparent edges at delivery resolution. Record export time and render the same selected frame twice. Run a short Egyptian Arabic mouth-cue test if Arabic dialogue is a requirement for the pilot.

A separate app becomes useful when the workflow needs a reusable cast library, an editable shot timeline, take review and revision, or a render queue. The project and shot format from the pilot can carry into that app. If full Rigby2D stage framing is essential before then, the editor can render a Film shot for Remotion to assemble. For unattended scene rendering, test a pinned JS runtime capture against editor output before adopting that route.
